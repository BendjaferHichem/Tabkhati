# 🍳 طبختي — مساعد اقتراح الوجبات

موقع ويب عربي بالكامل (RTL) يساعد المستخدم على معرفة "ماذا سنطبخ اليوم؟"
بناءً على المكونات المتوفرة لديه في المنزل والوقت الذي يملكه.

## ✨ الميزات

- اختيار المكونات من أقسام "الثلاجة" (خضروات، لحوم، ألبان وبيض، حبوب ونشويات،
  معلبات، أساسيات) أو عبر البحث المباشر — **وأيضاً إضافة أي مكوّن غير موجود
  في قائمتنا كمكوّن حر** (مثال: "لحم ماعز")، فلا يُقيَّد المستخدم بقائمة جاهزة فقط.
- خوارزمية مطابقة حتمية (بدون ذكاء اصطناعي) تحسب نسبة تطابق كل وصفة مع
  المكونات المتوفرة، مع تمييز المكونات الأساسية والاختيارية عن المطلوبة.
- طبقة ذكاء اصطناعي (**Groq API**) تشرح التوصيات بلغة عربية طبيعية، مع
  اقتراح بدائل — ويستمر الموقع بالعمل بشكل كامل حتى لو تعطّل الذكاء الاصطناعي.
- أكثر من 55 وصفة عربية وعالمية واقعية ومتنوعة في قاعدة بيانات SQLite.
- بطاقات وصفات بلمسة بصرية غنية (تدرّجات لونية دافئة + رمز الطبق) بدل رمز
  صغير فقط — انظر قسم "الصور" أدناه لتوضيح سبب هذا الخيار بدل صور فوتوغرافية.
- زر "🎲 فاجئني" بعشوائية حقيقية الآن (يسحب من كل الوصفات المطابقة، وليس
  من مجموعة صغيرة ثابتة).
- صفوف قابلة للتمرير أفقياً (الأقسام، الأفكار السريعة) مع **أسهم واضحة**
  للتمرير بالنقر، إضافة إلى التمرير باللمس المدعوم أصلاً على الجوال.
- صفحة **"تصفح وصفات جديدة"**: بطاقة مميزة تتجدد تلقائياً كل بضع ثوانٍ عبر كل
  الوصفات (مع أزرار تنقّل يدوية)، وشبكة كاملة قابلة للتصفية حسب نوع الوجبة
  ولإعادة الخلط بضغطة زر — كل ذلك من نفس الوصفات المخزّنة، دون أي تبعية خارجية.
- صفحة **"المفضلة"** لعرض كل الوصفات المحفوظة في مكان واحد.
- وضع طبخ تفاعلي خطوة بخطوة.
- تصميم متجاوب بالكامل (موبايل، تابلت، وسطح مكتب)، بدون الحاجة لإنشاء حساب.
- كل البيانات الشخصية (المكونات المختارة، المفضلة) تُخزَّن محلياً في
  المتصفح (localStorage) — لا يوجد تسجيل دخول في هذه النسخة.

### 🖼️ عن الصور

كل وصفة تحتوي بنية تقنية جاهزة لعرض صورة حقيقية (`image_url` في قاعدة البيانات
و`<img>` في الواجهة)، مع سقوط تلقائي وسلس إلى بطاقة "هيرو" ملوّنة (تدرّج +
رمز الطبق) إن كان الرابط فارغاً أو تعذّر تحميل الصورة — فلا تظهر صورة مكسورة
أبداً مهما حدث.

**4 وصفات فقط** تحتوي حالياً على صورة حقيقية مُتحقّق منها من ويكيميديا كومنز
(شكشوكة، حمص بالطحينة، عجة البطاطس، خبز محمص بالبيض والحليب) — كإثبات لعمل
الآلية بالكامل. لم يكن ممكناً عملياً إيجاد صور دقيقة لبقية الـ53 وصفة بجهد
معقول: نتائج البحث نادراً ما تكشف رابط صورة مباشر وقابل للاستخدام، وأغلب صور
المدونات لا تملك رابطاً مباشراً مستقراً. بقية الوصفات تعرض البطاقة الملوّنة
كخيار احتياطي جيد المظهر بدل صور مفقودة أو غير دقيقة.

**لإضافة صورة لأي وصفة بنفسك (دقيقتان لكل وصفة):**
1. ابحث عن اسم الطبق في Google Images أو أي موقع وصفات.
2. اضغط بالزر الأيمن على الصورة المناسبة واختر "نسخ عنوان الصورة" (Copy image address).
3. افتح `data/recipes.js`، وابحث عن الوصفة (بالاسم العربي `arabic_name`).
4. أضف `image_url: 'الرابط الذي نسخته',` بجانب `image_emoji` في نفس الوصفة، مثال:
   ```js
   image_emoji: '🍲', image_url: 'https://example.com/photo.jpg', estimated_cost: 'اقتصادي', ...
   ```
5. شغّل `npm run seed` من جديد لتحديث قاعدة البيانات.

بما أن هذا المشروع للاستخدام الشخصي، لا مشكلة في استخدام صور من مواقع وصفات
حتى لو كانت تحمل علامة مائية — الآلية تعرضها كما هي دون أي معالجة.

## 🧱 التقنيات المستخدمة

- **Backend:** Node.js + Express
- **Database:** SQLite (عبر `better-sqlite3`) — تم اختيارها لأنها لا تحتاج
  خادم قاعدة بيانات منفصل، وتعمل من ملف واحد، وهي الأنسب لمشروع يمكن نشره
  بسهولة وبتكلفة منخفضة. يمكن استبدالها لاحقاً بـ PostgreSQL دون تغيير كبير
  في منطق التطبيق (طبقة الوصول للبيانات معزولة في `server/database` و
  `server/services/matcher.js`).
- **AI:** Groq API (نموذج `llama-3.3-70b-versatile` افتراضياً، قابل للتغيير)
- **Frontend:** HTML/CSS/JavaScript عادي (بدون إطار عمل) لأداء أسرع وحجم أصغر

## 🚀 التشغيل محلياً

### المتطلبات
- Node.js 18 أو أحدث

### الخطوات

```bash
# 1. تثبيت الحزم
npm install

# 2. نسخ ملف البيئة وتعديله
cp .env.example .env
# افتح .env وأضف مفتاح Groq الخاص بك (اختياري — الموقع يعمل بدونه)

# 3. تهيئة قاعدة البيانات وإدخال بيانات الوصفات
npm run seed

# 4. تشغيل الخادم (وضع التطوير مع إعادة التحميل التلقائي)
npm run dev

# أو تشغيل عادي
npm start
```

بعد التشغيل، افتح: **http://localhost:3000**

### إعادة التهيئة
تشغيل `npm run seed` مرة أخرى في أي وقت يمسح البيانات القديمة ويعيد إدخالها
من `data/ingredients.js` و `data/recipes.js`.

## 🔑 متغيرات البيئة (`.env`)

| المتغير         | الوصف                                                       |
|------------------|--------------------------------------------------------------|
| `GROQ_API_KEY`   | مفتاح Groq API (احصل عليه من console.groq.com/keys). اختياري — بدونه يعمل الموقع بالاعتماد فقط على خوارزمية المطابقة. |
| `GROQ_MODEL`     | اسم النموذج المستخدم في Groq. القيمة الافتراضية: `llama-3.3-70b-versatile`. |
| `DATABASE_URL`   | مسار ملف قاعدة بيانات SQLite. اختياري.                        |
| `PORT`           | منفذ تشغيل الخادم. القيمة الافتراضية: `3000`.                 |

**مهم:** لا تضع مفتاح Groq مباشرة في الكود، ولا ترفع ملف `.env` إلى GitHub
(هو مستثنى بالفعل في `.gitignore`).

## 🔌 واجهات الـ API الرئيسية

| المسار                     | الوصف                                              |
|----------------------------|-----------------------------------------------------|
| `GET  /api/ingredients`    | قائمة المكونات (مع `?q=` للبحث)                    |
| `GET  /api/recipes`        | كل الوصفات                                          |
| `GET  /api/recipes/:id`    | تفاصيل وصفة واحدة                                   |
| `GET  /api/recipes/random` | وصفة عشوائية حقيقية (لزر "فاجئني")، تقبل `?ingredientIds=&timeAvailable=&preferences=` |
| `POST /api/recommendations`| المطابقة + شرح الذكاء الاصطناعي، تقبل `customIngredients: string[]` لمكونات حرة خارج القائمة |

## 🧠 كيف تعمل خوارزمية المطابقة؟

1. لكل وصفة، تُقسَّم المكونات إلى: **مطلوبة**، **اختيارية**، و**أساسية**
   (مثل الملح والزيت — تُعتبر متوفرة دائماً ولا تُحسب ضمن الناقص).
2. تُحسب نسبة التطابق بوزن أعلى للمكونات المطلوبة من الاختيارية، حتى لا
   تُخفِّض المكونات الاختيارية الترتيب بشكل غير عادل.
3. تُرتَّب النتائج حسب: نسبة التطابق ← أقل عدد مكونات ناقصة ← الوقت الأقصر ←
   الأعلى شعبية ← الأسهل تحضيراً.
4. تُرسَل أفضل النتائج فقط إلى Groq API لتوليد شرح عربي طبيعي — الذكاء
   الاصطناعي لا يختار الوصفات ولا يخترعها، بل يشرح فقط ما اختارته الخوارزمية.
5. إن تعذّر الوصول إلى Groq API (مفتاح مفقود، انقطاع الشبكة...)، يستمر
   الموقع بعرض النتائج نفسها بدون قسم الشرح، مع رسالة واضحة للمستخدم.

## 🚢 النشر (Deployment)

المشروع عبارة عن تطبيق Node.js/Express عادي، لذا يمكن نشره على أي منصة تدعم
Node.js (Render، Railway، Fly.io، VPS خاص...). تأكد من:
- تعيين متغيرات البيئة (خصوصاً `GROQ_API_KEY`) من لوحة تحكم المنصة.
- تشغيل `npm run seed` مرة واحدة بعد أول نشر لتهيئة قاعدة البيانات.
- إن كانت المنصة توفر تخزيناً دائماً (persistent disk)، اضبط `DATABASE_URL`
  ليشير إلى مسار داخل ذلك التخزين حتى لا تُفقد البيانات عند كل إعادة نشر.

## 📌 ملاحظات وتوسعات مستقبلية

- النسخة الحالية لا تتطلب تسجيل دخول؛ يمكن إضافة حسابات لاحقاً دون التأثير
  على تجربة "الاستخدام الفوري".
- ميزة "استخدم ما لديك قبل أن يضيع" (تحديد أولوية للمكونات القريبة من
  الانتهاء) يمكن إضافتها بسهولة عبر توسيع خوارزمية `matcher.js` لتُعطي وزناً
  إضافياً لمكونات معيّنة.
- المكوّن الحر الذي لا يُربط بأي مكوّن معروف (مثل "لحم ماعز") لا يرفع نسبة
  التطابق حالياً لأنه لا توجد وصفات فعلية تستخدمه، لكنه يُرسَل للذكاء
  الاصطناعي كسياق إضافي. توسيع قاعدة بيانات المكونات لاحقاً (أو إضافة
  وصفات جديدة) يجعل مثل هذه المكونات مؤثرة فعلياً في الترتيب.
- خطة أسبوعية وقائمة تسوق تلقائية (كانتا في نسخة سابقة) أُزيلتا لصالح صفحة
  "تصفح وصفات جديدة" بناءً على تفضيل صريح؛ يمكن إعادتهما لاحقاً كصفحة
  منفصلة إن دعت الحاجة دون التأثير على بقية البنية.
